# flyer-review 運用ルール

目的: チラシ（Canva）と、各媒体向けの告知・報告文を安全に作成・レビューするための一時フォルダ。

## フォルダで扱う3種類のコンテンツ

### 1. チラシ画像レビュー（Canva）
- Canva本体は編集できないため、レビュー・提案のみ行う。
- PNG/PDFをこのフォルダに置く → 提案を `proposals.md` に追記する → 確認後、画像と`proposals.md`は削除（個人情報保護のため）。
- GitHubへは原則push しない。

### 2. 告知文（開催前）→ `01開催告知/`
イベント告知の文面。媒体ごとに**読者が違う**ため、同じ情報でも書き方を変える。
同じ回の告知（Instagram/DM/LINE）はこのフォルダにまとめて入れることで、その回の告知セットを一気に作れるようにする。

**出すタイミング：次回の告知は、前回の開催日あたりに活動報告とあわせて出す。** 参加した直後がいちばん関心が高く、報告と次回案内を1回の連絡にまとめられるため。日程が先に決まっていても、早出しはしない（例：第8回11/15は2026-09-02に日程・ページとも確定していたが、告知は第7回9/27の前後に行う）。

### 3. 報告文・フォローメール（開催後）→ `02終了お知らせ/`
開催した回の様子を振り返る文面（note活動報告、Instagram、X投稿など）。

**出す順番：note公開 → Instagramフィード → ストーリーズ → LINEグループ → Doorkeeperフォローメール。** noteの記事URLが他のすべてで必要になるため、noteを先に出す。参加を迷っている人への安心材料にもなるため、基本は前向き・具体的なエピソード中心。
フォルダ分けの基準は**内容**。「告知」か「報告」かで振り分け、ファイル名も内容に合わせて`-post`（告知）/`-report`（報告）を使い分ける。

## 告知文：媒体別ルール（読者の違いで書き分ける）

| 媒体 | 読者 | 書き方の方針 |
|------|------|------|
| **Instagram** | CoderDojoをまだ知らない・未登録の人も見ている（ハッシュタグ経由の新規流入が前提） | 毎回、活動の基本情報（何をする体験か／対象年齢／無料）を省略せず入れる。「初めての人向け」の説明として書く。参加ハードルを下げる一言（未経験歓迎など）を必ず入れる。<br>⚠️ **Threadsにも同じ文面を出すなら500字以内**（ハッシュタグも字数に含まれる）。Instagram単独なら2200字まで。兼用する前提で短縮版を用意しておくとよい。 |
| **Doorkeeper DM** | メンバー登録はしているが、まだ参加したことがない人を含む | CoderDojo自体の説明は簡略化してよいが、「参加への後押し」を厚めに。同伴条件・持ち物など不安を解消する情報を丁寧に。個別に送る前提の、やや丁寧な文体。 |
| **LINEグループ** | 既に一度以上参加したことがある人（＝関係性ができている） | 基本説明はほぼ不要。開催告知はシンプルに、事務連絡（日程・会場・申込リンク）中心。カジュアルな文体でOK（「こんばんは！星です。」など）。 |

告知文を書く・レビューする際は、まずこの表でどの媒体かを確認し、対応する読者に合わせて情報の粒度と文体を調整すること。

## 報告文：媒体別ルール

| 媒体 | 読者 | 書き方の方針 |
|------|------|------|
| **X（旧Twitter）** | 公開・不特定多数 | 280字制限。当日の様子を一言で。次回日程があれば添える。 |
| **note活動報告** | 公開（noteのフォロワー含む） | エピソード中心でやや長め。参加した子どもたちの様子を具体的に描写する。**報告の本体はここ**。他の媒体はここへの導線になる。 |
| **Instagramフィード** | 公開（ハッシュタグ経由の新規も見る） | **報告は数行で十分。** 当日の空気が伝わるトピックだけ拾い、詳しくはnoteに送る（告知文と違って、ここで全部説明しない）。<br>⚠️ Threads兼用なら500字以内（告知文と同じ制約）。 |
| **Instagramストーリーズ** | 公開・24時間で消える | **3〜4行の短文のみ。** 内容を語らず「終わったこと」「報告があること」「次回日程」だけ伝えてリンクに送る。残したい場合はハイライトにまとめる。 |

### Instagramからnoteへの導線（固定運用）
- **プロフィールのリンクは、noteの活動報告マガジントップ。** 回ごとに貼り替えていないので、フィード投稿には「プロフィールから」と書けばよい（差し替え作業は不要）
- **個別記事に直接送りたいときは、ストーリーズのリンクスタンプを使う。** フィード投稿からは個別記事に飛ばせないため
| **LINEグループ** | 既に参加したことがある人 | **3〜5行でよい**（2026-09-27に確定した方針）。当日の様子は書き直さず、**アルバム追加の連絡・note記事のURL・次回の申込みリンク**の3点に絞る。写真が上がったことが参加者にとっていちばんの知らせなので1行目に置く。 |
| **Doorkeeperフォローメール** | **当日参加した人だけ** | 公開の報告とは別物。CoderDojoの説明も参加の呼びかけも不要。お礼・note記事の案内・**LINEグループへの誘導**の3点に絞る。関心がいちばん高い直後に一度だけ送る。 |

## フォルダ構成
```
flyer-review/
├── 01開催告知/       … 開催前の告知文（Instagram / Doorkeeper DM / LINE）
├── 02終了お知らせ/   … 開催後の報告文（X / note 活動報告）
├── README.md
├── proposals.md            … チラシ画像レビューの提案
├── *-copy-short-set.md     … チラシ文言たたき台（日付なし・随時更新）
└── (チラシ画像・PDF)       … レビュー後は削除
```

## ファイル命名規則
- 告知文（`01開催告知/`）: `doorkeeper-dm-YYYY-MM-DD.md` / `line-group-message-YYYY-MM-DD.md` / `instagram-post-YYYY-MM-DD.md`
- 報告文（`02終了お知らせ/`）: `{媒体}-report-{回数}-YYYY-MM-DD.md`（例: `x-report-5th-2026-06-28.md` / `note-report-5th-2026-06-28.md` / `instagram-report-5th-2026-06-28.md`）
- 参加者向けフォローメール（`02終了お知らせ/`）: `{媒体}-followup-{回数}-YYYY-MM-DD.md`（例: `doorkeeper-followup-7th-2026-09-27.md`）
- LINEグループは告知と報告でファイル名が変わる: 告知 `line-group-message-YYYY-MM-DD.md` / 報告 `line-group-report-{回数}-YYYY-MM-DD.md`
- **Instagramのストーリーズは独立ファイルにしない。** 同じ回の `instagram-report-*.md` の中に「ストーリーズ」セクションとして置く（フィード投稿とセットで使い、単独では成立しないため）。告知文で短縮版と長い版を1ファイルにまとめているのと同じ考え方。
  - ファイル名だけで種類が分かるよう、`-post`（告知）/ `-report`（公開の報告）/ `-followup`（参加者への直接連絡）を使い分ける。
- チラシ文言たたき台: `*-copy-short-set.md`
- 日付は開催日（複数イベントをまとめて告知する場合は `YYYY-MM-DD-YYYY-MM-DD`）

## 運用ポリシー
- GitHubへの push は、個人情報を含む画像・PDFを除いて基本的に問題ない（テキストドラフトはこれまでも commit してきた実績あり）。ただし画像・PDFは確認後に削除する。
- 個人情報が含まれる可能性がある画像・PDFは、このフォルダ内だけで扱い、作業完了後に削除する。
- LP/Doorkeeper本文（`content/`）との文言の齟齬がないか、確定前に確認する（同伴条件・友達参加案内など統一文面は特に注意）。
